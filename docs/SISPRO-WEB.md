# Sispro Web — ambiente isolado
Build: npm test && npm run build -- --mode web. O modo preview do Pages e o build desktop normal permanecem independentes.
Vercel: VITE_SUPABASE_URL e VITE_SUPABASE_PUBLISHABLE_KEY (somente sb_publishable_, nunca service_role/secret). Sem variáveis válidas, acesso web bloqueado.
Criar projeto Supabase exclusivo, desabilitar cadastro público e login anônimo, configurar URL do site, MFA e limites; aplicar supabase/schema/sispro-web.sql por migration após revisão. Criar usuários via painel Auth e inserir perfil autorizado (active=true) no painel SQL; função admin não recebe acesso aos autos de outros usuários, apenas consulta perfis. Alteração de roles e usuários via painel, não pelo navegador.
Cada conta tem um documento JSONB versionado (limite 5 MiB) com as coleções do aplicativo. RLS restringe por auth.uid e perfil ativo; escrita otimista rejeita conflitos. Sessão em memória, expira sem refresh; recarregar exige novo login. Sem sincronização entre Desktop e Web, compartilhamento setorial, upload PDF Web ou atualização em tempo real entre abas. Não importar dados locais automaticamente. Limitação: snapshot integral por operação, não recomendado para escala sem normalização. Não usar dados sigilosos antes de testes reais de autenticação, RLS entre duas contas e revogação, MFA, backup, auditoria e revisão LGPD.
